# Code Audit & Refactoring Roadmap (2026-01-18)

## 1. Audit Findings

### Code Smells & Readability
*   **Monolithic Script**: `verne_durand.py` (300+ lines) handles configuration, git operations, API interaction, and plan management. This makes it hard to test and maintain.
*   **Duplicated Logic**: `PlanManager` logic exists in `verne_durand.py` and partially in `tools/mark_done.py`. Both parse the YAML structure independently.
*   **Feature Envy**: The main script intimately knows the structure of `session` objects (outputs, PR details), rather than delegating to a helper.
*   **Long Methods**: `run_jules_task` and `wait_for_session` perform multiple distinct operations (polling, logic, printing).

### Performance Optimization
*   **Inefficient IO**: `PlanManager` re-reads the YAML plan file from disk on every method call (`get_pending_tasks`, `move_to_started`, etc.). In the main loop, this results in excessive file reads.
*   **Polling Loop**: The polling interval is fixed at 30s. While not a major bottleneck, the status checking loop could be more event-driven or optimized.

### Software Architecture & Design
*   **SRP Violation**: `verne_durand.py` has too many responsibilities. It should be a thin orchestrator.
*   **Lack of Abstraction**: Git commands are constructed as raw lists throughout the code. A `GitClient` abstraction is needed.
*   **Hard Dependencies**: The code relies on global state (env vars) scattered throughout functions.

### Security Vulnerabilities
*   **Input Handling**: While `subprocess.run` usage is generally safe (list args), there is no strict validation of branch names or PR URLs beyond regex extraction.
*   **Error Swallowing**: `wait_for_session` catches `(JulesAPIError, Exception)` and just prints `?`, potentially masking critical auth or quota errors.

### Error Handling
*   **Silent Failures**: If `PlanManager` fails to load, it sometimes returns empty defaults which might confuse the orchestrator.
*   **Retry Logic**: The retry logic is simple but effective. However, `wait_for_session` timeout handling is mixed with API error handling.

### Documentation & Consistency
*   **Good Coverage**: README is detailed.
*   **Consistency**: `tools/` scripts duplicate some logic found in the main script.

## 2. Refactoring Roadmap

### Phase 1: Component Extraction (Foundation)
*Focus: Creating reusable, testable library modules without breaking the existing application.*

#### Task: 1-1-extract-plan-module
*   **Detail**: Create `lib/plan.py`.
    *   Implement `PlanManager` class.
    *   Logic: Initialize with filepath, `load()`, `save()`, methods for `get_next_task()`, `mark_complete()`, `mark_started()`.
    *   Refinement: Store loaded data in memory and only `save()` when modified. Add a `reload()` method to refresh from disk explicitly.
    *   File: `lib/plan.py` (New).
*   **Definition of Done**: Unit tests in `tests/test_plan.py` verify loading, saving, and state transitions work correctly.
*   **Verify**: Ensure all tests pass.

#### Task: 1-2-extract-git-module
*   **Detail**: Create `lib/git.py`.
    *   Implement `GitClient` class or helper functions.
    *   Logic: Move `run_git_cmd`, `ensure_repo_initialized`, `ensure_work_branch`, `push_changes`, `get_repo_slug` from `verne_durand.py`.
    *   File: `lib/git.py` (New).
*   **Definition of Done**: Unit tests in `tests/test_git.py` (mocking subprocess) verify git commands are constructed correctly.
*   **Verify**: Ensure all tests pass.

#### Task: 1-3-extract-ui-module
*   **Detail**: Create `lib/ui.py`.
    *   Logic: Move `ColorFormatter` class and `configure_logging` function from `verne_durand.py`.
    *   File: `lib/ui.py` (New).
*   **Definition of Done**: A simple test script imports `configure_logging` and writes to stdout without error.
*   **Verify**: Ensure all tests pass.

#### Task: 1-4-extract-jules-module
*   **Detail**: Create `lib/jules.py`.
    *   Implement `JulesHelper` class or functions.
    *   Logic: Move `wait_for_session`, `apply_jules_changes`, `run_jules_task` (the API parts) from `verne_durand.py`.
    *   Refactor `wait_for_session` to accept a callback or return richer status objects.
    *   File: `lib/jules.py` (New).
*   **Definition of Done**: Unit tests in `tests/test_jules.py` (mocking `JulesClient`) verify session polling logic and PR extraction.
*   **Verify**: Ensure all tests pass.

### Phase 2: Core Integration
*Focus: Switching the main application to use the new libraries.*

#### Task: 2-1-refactor-verne-durand
